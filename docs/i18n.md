# i18n 接入与维护参考

- **日期**：2026-10-29
- **用途**：新增界面、补充翻译和扩展语言时确定改动范围与验证方式。
- **代码基线**：`main`，`1194be0b747a`；前端使用 i18next 26.5.11、react-i18next 17.1.9。
- **相关参考**：[架构说明](architecture.md)、[账号偏好 API](client-api.md#account-language-preferences)、[备份格式](export-format-v2.md)。
- **怎么读**：〔编号〕对应文末的代码入口、示例和命令。

## 现有行为

**目前只支持简体中文和 English。** 前端共用一个翻译实例，语言资源随前端打包。已有 key 以原文短语为主，中文和英文原文都有，没有按组件拆分 namespace。资源测试检查中英文 key 集合、插值变量和英文资源中的中文字符，但不能证明所有组件都已接入翻译。〔1〕

**语言由账号偏好和独立的访客选择共同决定。** 登录后，账号已保存的选择优先；账号未设置时使用当前浏览器的访客选择。访客没有保存选择时，按浏览器语言顺序寻找支持的语言，最后回退到简体中文。账号选择在服务端确认保存后生效，访客选择仅保存在当前浏览器；退出登录后恢复访客选择。跨设备恢复发生在重新加载账号会话时，不代表其他设备会实时切换。〔2〕

**切换语言只改变界面呈现。** 不翻译用户正文、昵称、链接、草稿内容或文档数据，不改变业务枚举、路由、标识、日期分区和站点时区。编辑器和页面不能因为语言变化而重新挂载。〔3〕

## 新增组件或修改文案

1. **先查现有消息。** 同一含义可复用现有 key；相同短语表达不同含义时，用更完整的原文区分。修改译文通常只改资源值，不要顺便重命名已有 key 或统一中英文 key 的风格。
2. **在组件渲染时翻译。** React 组件订阅语言变化，再生成标题、按钮、菜单、占位符、tooltip、空态、错误提示和无障碍名称。接收标题等 prop 的共享组件可以由调用方传入翻译后的值，但调用方必须能随语言重新渲染。纯函数在调用时读取翻译，不能在模块加载时保存翻译结果。〔4〕
3. **同步维护所有已支持语言。** 新消息与组件一起提交，不用回退语言掩盖漏翻译。完整句子放在资源里，动态值用插值；数量文案传入计数并维护所需复数形式，不用字符串拼接决定语序。用户内容只作为动态值展示，不当作翻译 key。〔5〕
4. **保留稳定数据。** 菜单配置、状态和文档存储稳定的 ID、枚举或消息 key；显示时再翻译。缓存的格式化结果必须区分语言；语言改变后需要更新的 effect、memo 和外部控件适配也要检查，不能只依赖组件顶部增加一次订阅。日期和数字复用公共格式化入口，业务日期分区继续使用原有入口。〔6〕
5. **复用字体与编辑器集成。** 普通界面继承公共字体栈，由浏览器逐字选择 Latin/CJK 字体；不要按界面语言给整块混合文本强制换字体，也不要为了翻译复制一套组件样式。编辑器只调整文案和已有扩展的配置，不通过重建 editor、重设正文或给根节点加语言 key 来刷新文字。〔7〕

新增一条翻译不需要修改账号 API、数据库或语言选择框。只有增加支持的语言，才进入下一节的完整流程。

## 新增一种语言

**新增语言需要前后端一起交付。** 当前多个入口明确区分两种语言，增加资源文件并不会自动接通其余入口。下面是维护步骤，不是已完成的多语言能力。

1. **确定语言代码与覆盖范围。** 明确保存的标准代码、可映射的浏览器语言变体，以及语言名称的原文显示。不要新增“不是英文就当中文”的判断。需要从右向左排版的语言时，另行完成页面方向和组件交互的验证；现有语言切换只设置页面语言，没有提供整站方向切换。
2. **注册前端资源与识别规则。** 扩展语言类型、运行时校验、资源注册、支持列表、浏览器匹配和当前语言读取。当前读取函数把非英文结果返回为中文，必须一并修改。保持回退策略明确；加了新语言不等于要改变所有访客的默认语言。〔8〕
3. **补全语言入口和系统呈现。** 更新选择框选项、语言名称与副说明的语言标记、设置页当前选择、备份合并预览中的语言名称，以及 PWA manifest 的选择和对应文件。不能让新语言在这些位置仍显示中文或“未设置”。〔9〕
4. **打通账号保存与已有数据库。** 更新领域校验、CLI 帮助和 HTTP/CLI 测试。数据库列还有语言允许值约束，需要新增 migration 扩展约束并保留已有账号及其关联数据；只放宽 Go 校验仍会写入失败。不要修改已经执行过的旧 migration，迁移账本会校验历史文件。UI 继续通过原有偏好服务保存，不增加组件自己的请求、持久化或账号缓存。〔10〕
5. **覆盖导出与恢复。** 检查全站和个人备份中的语言值能通过校验、导出、导入和合并。保留既有规则：替换恢复账号偏好；合并时匹配到的本地账号保留本地选择，新增账号带入自己的选择。字段形状没变不代表可以跳过新语言值的往返测试。同步更新 API、CLI 和备份说明。〔11〕
6. **完成资源与运行验证。** 翻译完整资源，覆盖插值、复数、日期、相对时间、数字、长文案和混排。将当前只比较中英文的资源测试扩展到新语言；复数类别不同时按消息及该语言需要的形式检查，保留缺项和插值校验。验证访客保存、登录恢复、保存失败、退出登录、刷新和编辑中切换，并验证已有数据库升级后数据保留。〔12〕

## 多人修改时怎么避免冲突

- **一个功能包含自己的翻译。** 组件、各语言资源和相关测试保持在同一改动里，避免先合并界面、以后再补语言。新增语言则作为一个包含完整边界的改动交付，避免前端可选但服务端无法保存。
- **保持资源 diff 小。** 沿用现有排列和格式，只改需要的条目；不要在功能 PR 中全量排序、重新生成或搬迁语言资源，也不为单个组件引入第二套翻译实例或 namespace。
- **合并新增条目时取并集。** 手动保留两边不同的新消息，在所有语言中同步处理。不要用整份 ours/theirs 覆盖资源；同一个 key 被赋予不同含义时，先统一含义或拆分消息，不能只消除 JSON 冲突标记。
- **删除或改 key 前检查调用。** 除直接翻译调用外，还要检查菜单配置、纯函数、动态消息选择和测试。JSON 重复 key 会在解析时覆盖旧值，现有资源集合测试不能替代重复项检查。
- **合并后检查最终结果。** 重新跑资源与受影响组件测试，核对两边的消息都能在实际页面切换。补齐 key 集合只能验证资源完整性，不能替代组件订阅和浏览器验证。
- **参考随实现更新。** 语言入口、资源组织、偏好协议或测试能力改变时，同步修改对应条目；新增普通组件按现有流程接入，不因一条文案变更扩展整套机制。

## 验收范围

| 改动                   | 至少确认                                                           |
| ---------------------- | ------------------------------------------------------------------ |
| 修改译文               | 资源与插值校验；受影响界面在各语言中的语义和显示                   |
| 新增组件文案           | 上述检查；组件保持挂载时切换，正文与输入状态保留，无障碍名称同步   |
| 修改格式化或编辑器文案 | 上述检查；语言改变后的缓存、外部控件文字及编辑状态，日期分区不变   |
| 新增语言               | 前端识别、账号 API/CLI、已有库迁移、备份往返、PWA 和真实浏览器布局 |

自动测试默认从中文开始，双语测试要显式切换并断言结果。浏览器检查使用现有共享 playground 的独立前端预览，保留其数据与生产实例的隔离。字体、换行和溢出必须看实际浏览器；jsdom 断言不能证明视觉一致。〔13〕

## 附录：代码入口与操作示例

以下入口核对基线为 `main` 的 `1194be0b747a`；路径以仓库根目录为基准。接入时以当前代码为准。

### 〔1〕翻译实例与当前检查能力

- `web/src/i18n/index.ts`：唯一 i18next 实例，`keySeparator: false`、`nsSeparator: false`，原文中的句点和冒号不作为层级分隔符。
- `web/src/i18n/locales/zh-CN.json`、`web/src/i18n/locales/en.json`：当前平铺资源。
- `web/src/i18n/i18n.test.ts`：目前仅比较中英文 key 集合和插值变量，并排除英文译文中的 CJK 字符；没有组件文案覆盖扫描。

### 〔2〕语言选择和保存链路

`App` → `SessionProvider` → `LanguageProvider`。访客选择由 `visitorLocale()` 读取 `moment.ui-locale`，再匹配 `navigator.languages`。账号会话携带 `preferences.uiLocale`，服务端字段为 `ui_locale`。

- `web/src/i18n/LanguageProvider.tsx`：`saveLanguage()`、`document.documentElement.lang` 和 manifest 切换。
- `web/src/components/LanguageDialog.tsx`：暂存选择、取消、保存失败和会话变化处理。
- `web/src/features/auth/SessionProvider.tsx`：`applyPreferences()` 同时核对账号 ID 和 CSRF token，避免结束或更换会话后应用迟到响应。
- `web/src/api/preferences.ts`：偏好响应解析和 `PATCH /api/v1/account/preferences` 客户端；读取偏好也包含在账号会话中。
- `internal/transport/http/gin/account_preferences.go`：GET/PATCH 路由及字段校验。

### 〔3〕呈现与业务数据的边界

- `web/src/features/timeline/timelineDays.ts`：`siteDate()` 按站点时区生成稳定日期分区，不随 UI locale 改变。
- `web/src/i18n/LanguageProvider.test.tsx`：切换后输入节点与草稿保留；保存失败、访客选择和迟到响应行为。
- 正文、用户名称、URL、业务枚举和 Tiptap 文档节点不是翻译 key。

### 〔4〕React 组件与非 React helper

```tsx
import { useTranslation } from "react-i18next";

export function SaveButton() {
  const { t } = useTranslation();
  return <button type="button">{t("保存")}</button>;
}
```

非 React helper 从公共 i18n 入口导入 `t`，在函数调用时执行。模块级配置保存原始 key；渲染时调用 `t(action.labelKey)`。不要写模块级 `const label = t("保存")`，也不要把翻译后的字符串当作菜单命令 ID。纯 helper 不会订阅 React 更新，渲染其结果的组件仍需 `useTranslation()`。

现有示例：`web/src/features/people/SuggestedPeople.tsx` 在订阅语言后生成卡片标题；`PeopleCard.tsx` 用同一个 title 设置标题和 `aria-label`。

### 〔5〕插值与复数

- 插值使用 `t("回复 {{value1}}", { value1 })`；每种语言必须保留同名变量，不能先把值拼进 key。
- 复数调用必须传 `count`。参考 `web/src/features/compose/Composer.tsx` 的附件数量提示和资源中的 `_one`、`_other` 条目；英文形式不能直接代表其他语言的全部形式。
- 当前 `escapeValue: false` 依赖 React 文本输出的转义。普通翻译继续作为 React 文本渲染，不把插值结果交给 `dangerouslySetInnerHTML`。

### 〔6〕格式化和缓存

- `web/src/i18n/format.ts`：`formatNumber()`、`formatDate()`、`formatRelative()`。
- `web/src/features/posts/dates.ts`：帖子日期的站点时区显示。
- `web/src/features/article/articleDates.ts`：显示 formatter 的缓存 key 包含 locale、timezone 和显示选项；用于业务年份判断的 formatter 保持独立。
- `web/src/features/article/editor/autosave.ts`：状态标签在读取时翻译，而非把翻译结果存入状态枚举。

### 〔7〕字体和编辑器

- `web/src/styles/global.css`：公共 `--font-sans`；普通界面已有 400、500、700、800 四种字重及逐字回退。不要复制成组件自己的同名字体声明。
- `web/src/features/article/editor/ArticleEditor.tsx`：编辑器实例、扩展和 React UI 集成。
- `web/src/features/article/editor/schema.ts`：placeholder 使用回调读取公共翻译。
- `web/src/features/article/editor/vendor/notion/`：现有编辑器 UI 和 hooks 中的文案适配；保留其原有命令、焦点、键盘和节点交互。

### 〔8〕新增语言的注册入口

### 〔9〕容易漏掉的语言呈现入口

- `web/src/components/LanguageDialog.tsx`：选项和主副语言名称的 `lang` 标记，当前存在中英文二选一逻辑。
- `web/src/features/settings/LanguageSettings.tsx`：当前语言名称，当前非英文直接显示中文。
- `web/src/features/settings/BackupRestore.tsx`：合并预览的 `ui_locale` 显示，当前只识别中英文。
- `web/src/i18n/LanguageProvider.tsx`、`web/public/manifest.webmanifest`、`web/public/manifest.en.webmanifest`：当前 manifest 选择也是二选一；新增文件保留相同应用 id、scope 和 start_url。

### 〔10〕服务端与数据库

- `internal/domain/locale.go`：`ValidateUILocale()`。
- `internal/app/account_preferences.go` → `internal/storage/sqlite/account_preferences.go`：独立偏好写入，不经过公开 profile 更新。
- `internal/transport/cli/preferences.go`：`user get-preferences`、`user update-preferences --ui-locale`；`auto` 保存 null。
- `internal/storage/sqlite/migrations/0006_account_language.sql`：现有列约束只接受 null、zh-CN、en。
- `internal/storage/sqlite/migration.go`：历史 migration checksum 校验、事务和外键检查。增加语言值时新增后续 migration，不修改旧文件；若重建 users，验证原列、账号关联、索引和数据都保留。

### 〔11〕备份与契约

- `internal/archive/export.go`、`internal/archive/merge.go`、`internal/archive/merge_review.go`：偏好字段、语言值校验和合并。
- `internal/storage/sqlite/archive.go`、`internal/storage/sqlite/import.go`：归档存储与导入校验。
- `docs/client-api.md`、`docs/export-format-v2.md`：允许值、偏好 API/CLI 和恢复规则。

### 〔12〕扩展语言时的测试入口

`web/src/i18n/i18n.test.ts`、`web/src/i18n/LanguageProvider.test.tsx`、`web/src/api/preferences.test.ts`、`web/src/features/people/SuggestedPeople.test.tsx`。

服务端检查覆盖 `internal/domain`、`internal/app`、`internal/storage/sqlite`、`internal/transport/http/gin`、`internal/transport/cli` 和 `internal/archive`。具体修改哪个入口，就保留或增加对应的新值、拒绝非法值、保存失败、迁移保留数据与备份往返测试，不通过扩大 mock 的允许范围替代真实路径验证。

### 〔13〕验证命令

从仓库根目录运行，按改动范围选择：

```sh
mise exec -- pnpm --dir web test src/i18n src/api/preferences.test.ts
mise exec -- pnpm --dir web test src/features/people/SuggestedPeople.test.tsx
mise exec -- pnpm --dir web lint
mise exec -- pnpm --dir web build
mise exec -- pnpm --dir web format:check
mise exec -- go test ./internal/domain ./internal/app ./internal/storage/sqlite ./internal/transport/http/gin ./internal/transport/cli ./internal/archive
```

新增组件时将第二条换成实际受影响测试。`web/src/test/setup.ts` 在每项测试前重置中文和浏览器存储；切换测试用 `act()` 等待 `i18n.changeLanguage()`，断言现有节点和编辑状态保留。

真实数据验证使用独立前端端口代理现有 18080 backend；本地已配置 Moment skills 时，按 `moment-dev-playground` 的共享数据流程启动。布局与字体用 `mise exec -- task layout -- --help` 查看浏览器检查入口；不要为了语言验证重置共享数据或修改生产账号偏好。
